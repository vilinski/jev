Decision Models: Accuracy vs. Cost and Speed

Typed yes/no, choice and score decisions from five hosted models on {NPUB} items of the public jev-bench. Bubble area is proportional to median latency, or to cost when latency is on the x-axis. Measured {NOW} · full report

Legend

Green gradient marks cheaper or faster with a better score. Dashed line marks the Pareto frontier: no other model is both cheaper (or faster) and better.

Cost is list price × tokens measured on the {NPUB} items. The sample is {PER} items per dataset, one run, so gaps under about 5 points are inside the 95% interval. The OpenAI Decisions API is in public beta; the DIY row is a chat model made to answer through token log-probabilities and cannot take questions with more than 26 options.

Method and data

Same questions to every model through the jev CLI (one question per request, sequential). Accuracy counts the top-probability option; Brier is the sum over options of (probability − label)²; a failed or refused request scores as uniform, following the method published with Celeris-1. Prices: Celeris $0.04, Jev $0.042, Cloudflare clef-flash $0.038, OpenAI Decisions $0.10 per 1M input tokens (output free); gpt-4.1-mini $0.40 in, $1.60 out. Latency includes process start and a fresh TLS connection per call, so it is higher than vendor-published figures. Full tables, per-dataset results and caveats: /jev-benchmark/.
